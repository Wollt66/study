# 答辩预测 Q&A（15题）

1. **为什么用 ECharts 而不是 D3.js？** ECharts 开箱即用，封装好了折线图、柱状图、饼图等常见图表，开发效率高；D3.js 更灵活但需要手动绘制，开发成本高。毕设场景下 ECharts 更合适。

2. **大屏为什么用固定分辨率+缩放，而不是响应式？** 大屏通常展示在固定尺寸的拼接屏或电视上，固定设计稿+等比缩放能保证设计效果不被破坏，响应式在大屏场景下反而容易导致布局错乱。

3. **多图表联动是怎么实现的？** App 组件维护 selectedCategory 状态，柱状图点击时回调更新状态，状态作为 prop 传给折线图和饼图，两个图表根据 prop 过滤数据后重新渲染。本质是 React 单向数据流。

4. **实时数据刷新为什么用 setInterval 而不是 WebSocket？** 毕设场景没有后端服务，setInterval 模拟推送足够展示效果。生产环境可以替换为 WebSocket 或 SSE，数据获取层抽象出来即可平滑切换。

5. **为什么用 Vite 而不是 Webpack？** Vite 开发模式基于浏览器原生 ES Module，启动速度快，热更新高效，配置简单，是目前 React 新项目的主流选择。

6. **为什么用 CSS Grid 而不是 Flexbox？** 大屏需要精确的二维行列划分，Grid 天然支持行和列的同时控制，Flexbox 是一维布局，需要嵌套多层。

7. **大屏的深色主题是怎么实现的？** 全局 CSS 设置深蓝背景，ECharts 的 textStyle、axisLine、splitLine 都配置为浅蓝色调，面板边框使用半透明蓝色。

8. **echarts-for-react 是什么？** 它是 ECharts 的 React 封装组件，接收 option prop 渲染图表，提供 onEvents 绑定事件、notMerge 控制是否合并配置等能力。

9. **如果数据量很大，图表卡顿怎么办？** ECharts 支持渐进式渲染（progressive）和数据采样（sampling），大数据量时可以开启。也可以使用 dataZoom 组件让用户缩放查看。

10. **为什么省份分布用横向柱状图而不是中国地图？** 中国地图需要引入 GeoJSON 地图数据，增加项目体积和复杂度。横向柱状图同样能展示省份排名，且实现简单。生产环境可以引入 echarts 地图扩展实现真正的地理可视化。

11. **大屏适配手机吗？** 大屏设计目标是 PC 端拼接屏/显示器，不考虑手机适配。手机端应该单独设计移动版页面。

12. **组件是怎么拆分的？** 按图表类型拆分为独立组件（LineChart、BarChart、PieChart 等），每个组件内部管理自己的数据获取和图表配置，通过 props 接收联动状态。ChartCard 是公共容器组件，统一边框样式。

13. **mock 数据是怎么生成的？** mock/data.ts 中定义了生成函数，使用 Math.random() 结合三角函数生成有规律的模拟数据，让图表看起来有真实波动趋势而不是完全随机。

14. **如果要对接真实后端，需要改哪些地方？** 将 useLiveData 中的 generator 函数替换为 fetch 调用后端 API 即可，组件层无需修改。如果是 WebSocket，则在 useEffect 中建立连接，onmessage 时 setState。

15. **做这个毕设最大的收获？** 掌握了 React 组件化开发和 ECharts 的使用，理解了大屏设计的适配方案和多图表联动的数据流设计，对前端数据可视化领域有了实践认识。
