## 一、需求与存量功能关系分析

### 1.1 存量代码现状

设计输入仅为《需求规格说明书》，**不存在任何存量业务代码**。本项目为从零开始的全新增量工程，因此：

- 已实现功能：无；
- 需要扩展的功能：无；
- 需要新增的功能：全部（下文全部设计均为新增）。

### 1.2 依赖的外部技术资产与约束

虽然没有存量代码，但设计受以下"外部存量资产"的硬约束，必须在方案层面提前消解：

| 外部资产 | 与需求的关系 | 对设计的约束 |
| --- | --- | --- |
| ECharts 5 | 全部图表的渲染基座 | **ECharts 5 起不再内置中国地图**，必须自行获取 geoJSON 并 `registerMap` 注册（FR-01/02/03 的前置条件） |
| 阿里 DataV geoJSON（areas_v3） | 全国/省级/市级地图边界数据唯一来源 | 需求 NFR-07 要求断网运行 → geoJSON 必须**本地打包**，禁止运行时在线拉取；且体积需控制 |
| Vue 3 / Pinia / vue-router 4 | 框架基座 | 组合式 API 写法；联动状态必须收敛到单一 Store（SSOT），避免组件间网状通信 |
| 浏览器 Fullscreen API | FR-21 全屏切换 | 需处理 webkit 前缀回退与 ESC 退出事件监听 |

### 1.3 范围裁剪决策（需求方已确认）

按已锁定技术决策：geoJSON 仅内置 **全国 + 4 个重点省份（广东 / 江苏 / 浙江 / 四川）+ 4 个对应省会城市（广州 / 南京 / 杭州 / 成都）**，其余省份/城市下钻时按 FR-03 的降级条款处理（明确提示"地图数据缺失"，当前视图与数据保持不变）。该裁剪在「十一、设计到需求映射表」中对 FR-02 的影响做了显式标注。

```
│                                                                             │

├─────────────────────────────────────────────────────────────────────────────┤
│  L2 Mock 数据引擎层（src/mock，纯 TS 无框架依赖，可单测）                    │
│                                                                             │
│  engine.ts(tick 调度/模拟时钟) ─ noise.ts(平滑噪声+双峰函数)                 │
│       ├─ entities.ts(实体工厂)  ├─ constants.ts(权重表/字典/枚举)             │
│       └─ aggregate.ts(自下而上聚合，保证口径一致)                            │
├─────────────────────────────────────────────────────────────────────────────┤
│  L1 资源层（src/assets + src/chart + src/styles）                           │
│                                                                             │
│  assets/geo/   china.json + 4 省 + 4 省会市 geoJSON（异步 chunk，断网可用）  │

数据自底向上流动：L2 tick ─▶ L3 snapshot ─▶ getters ─▶ L4 watch ─▶ L5 渲染

```

### 2.2 分层职责与依赖规则

1. **单向依赖**：L5 → L4 → L3 → L2 → L1，严禁反向依赖（mock 引擎不感知 Vue，保证可独立单测——NFR-10 模块化）。
2. **SSOT（单一数据源）**：全部业务数据（当前快照、过滤状态、钻取层级）只存在于 `screenStore`；图表组件是无业务状态的"渲染器"，接收派生数据 props。
3. **事件收敛**：所有联动入口（地图点击、扇区点击、图例点击）统一 emit 给 ScreenView，由其调用 Store action，图表之间互不感知。
4. **失败兜底**：geoJSON 缺失、下钻不可用等异常一律经 Store 的 `mapMissingTip` 状态驱动全局提示组件，组件自身不弹窗。

## 四、路由设计

### 4.1 路由模式选择

采用 **hash 模式**（`createWebHashHistory`）：构建产物无论以静态服务器还是本地文件方式打开均可正确路由，且断网/离线分发场景（NFR-07）无服务器 rewrite 依赖。history 模式在静态托管下需要 fallback 配置，属于不必要的部署风险。

### 4.2 路由表

| 路径 | 名称 | 组件 | 加载策略 | 职责 |
| --- | --- | --- | --- | --- |
| `/` | `screen` | `views/ScreenView.vue` | 首屏同步加载 | 主大屏：唯一业务界面，承载全部 FR |
| `/about` | `about` | `views/AboutView.vue` | 懒加载（`() => import(...)`） | 系统说明页：项目概述、技术栈、三大技术亮点原理图解、架构分层图；服务于答辩讲解，不参与业务数据流 |

### 4.3 路由级生命周期约定

- `ScreenView` 挂载时启动 MockEngine，**离开路由时必须停止引擎并触发全部图表 dispose**（防内存泄漏，NFR-12）；
- `/about` 为纯静态内容页，无 Store 订阅、无定时器；
- 两个页面共享同一 `App.vue` 根与全局霓虹样式基座。

### 5.3 关键组件设计说明

#### ScreenLayout.vue（缩放容器 + 版式）

- 内部调用 `useScreenAdapter`，对固定 1920×1080 的内层容器施加 `transform: translate(...) scale(...)`；
- 版式用 CSS Grid `grid-template-areas` 声明（header / left / center / right / bottom 五区），区域尺寸 px 写死；
- 全屏模式（FR-21）在此组件挂载：监听 Store 全屏状态，调用 Fullscreen API 并在卸载时移除监听。

#### KpiCard.vue（四实例）

- 四张卡配置由 ScreenView 静态定义：`拥堵指数(等级色标)`、`在途车辆数(辆)`、`今日事故数(起)`、`平均车速(km/h)`，数值全部来自 `store.filteredKpi`；
- 拥堵指数卡附五级色标条（与地图 visualMap 同一色带，满足数据质量约束 3）；
- 数值更新用 CSS `transition`（数字滚动由视图层插值，避免 JS 帧循环），保证 FR-14 即时更新不破版式。

#### ChartCard.vue（通用容器）

- 视觉契约：`border-radius: 14px`、深色半透玻璃底、`box-shadow` 双层辉光（外层青色 8px 低透明 + 内侧 1px 亮描边）、标题栏左侧霓虹渐变竖条；
- 具名插槽 `extra` 供卡片头右侧放操作（MapChart 的"返回上一级"按钮即放此处）；
- 所有图表组件一律包裹在 ChartCard 内，保证全屏视觉一致性（NFR-08/10：换图表不动容器）。

#### MapChart.vue（核心交互组件）

- 渲染结构：`geo` 底图（registerMap 注册名）+ `series[0]` 热力 choropleth（visualMap 五级色带）+ `series[1]` 事故 `effectScatter`（涟漪散点，severity 映射点径/颜色）；
- 钻取：`click` 事件命中地区 feature → 若 `drillableCodes` 含该 adcode 则 emit `region-click`，否则 emit `geo-missing`（FR-03 降级入口）；
- 返回：ChartCard `extra` 插槽中的"返回上一级"按钮 → emit `back`（level === 'country' 时隐藏）；
- tooltip（FR-05）：formatter 输出 区域名 / 拥堵指数（带等级色点）/ 在途车辆数 / 今日事故数；
- **实例复用原则**：切层级只 `setOption({ series: [{ map: 新注册名 }], ... })`，不销毁重建实例，避免闪烁与泄漏。

#### AccidentPieChart / VehicleRingChart（联动入口）

## 六、composables 设计

### 6.1 useECharts —— 图表实例生命周期托管

**动机**：12 个图表组件若各自裸写 init/resize/dispose，极易泄漏（NFR-12 长时运行稳定性）。统一封装为唯一 ECharts 接触点。

**签名（契约）**：

```text
useECharts(
  domRef: Ref<HTMLElement | null>,
  options: {
    theme?: 'neon'                      // 默认霓虹主题
    optionFactory: () => EChartsOption  // 每次重新计算的完整 option
    watchDeps: WatchSource[]            // 触发 setOption 的响应式依赖
    mergeMode?: 'merge' | 'notMerge'    // 默认 merge（性能，见 10.3）
  }
): {
  instance: ShallowRef<ECharts | null>  // 供高级调用（如手动 dispatchAction）
  refresh(): void                       // 立即按 optionFactory 重设
  resize(): void                        // 供外部触发
}
```

**生命周期规则**：

1. `onMounted` → `init(dom, 'neon')`，并首刷一次 option；
2. `ResizeObserver` 监听容器 → 防抖 150ms → `instance.resize()`（transform 缩放不触发 RO，只有真实窗口变化触发，避免连锁 resize 风暴）；
3. `watch(watchDeps)` → `setOption(optionFactory(), { mergeMode })`，动画时长统一 ≤ 400ms（NFR-02 ≤ 500ms 留裕量）；
4. `onBeforeUnmount` → `instance.dispose()` + `ResizeObserver.disconnect()` + 清防抖定时器，四件事原子完成，缺一即泄漏。

### 6.2 useScreenAdapter —— 等比缩放算法

**算法（伪代码）**：

```text
输入：designW=1920, designH=1080；实时 viewportW/H（window.innerWidth/Height）

scale    = min(viewportW / designW, viewportH / designH)   # 等比取小 → "contain"
offsetX  = (viewportW - designW × scale) / 2               # 水平居中
offsetY  = (viewportH - designH × scale) / 2               # 垂直居中

容器样式：
  position: fixed; left: 0; top: 0
  width: 1920px; height: 1080px            # 尺寸恒为设计稿像素
  transform-origin: left top
  transform: translate(offsetX px, offsetY px) scale(scale)
```

**溢出与居中处理说明**：

- `min` 保证任一方向都**不会溢出裁切**（FR-20"不出现内容裁切"）：窄边贴合、宽边留白；
- 留白区（letterbox）由 body 的深空背景 + 霓虹网格纹理填充，视觉上是有意设计而非"黑边"；
- 窗口 `resize`（防抖 100ms）与 `fullscreenchange` 事件均触发重算（FR-21 全屏后重新贴合）；
- 1366×768 时 scale ≈ 0.711，最小设计字号 14px 缩后约 10px，可读；2560×1440 时 scale = 1.333 放大无失真风险（矢量 DOM + canvas 高 DPR 渲染）。

**与 ECharts 的兼容机制（重要设计依据）**：zrender 的事件定位基于 `getBoundingClientRect()`（返回 transform 后的视觉盒）与 canvas 内部像素换算，`transform: scale` 容器下点击坐标与 tooltip 定位天然正确；该结论列入 §10 风险 R5 的早期验证项（spike 验证一次即可锁定）。

**选型对比（为何不用 rem / vw 方案）**：rem 需全量换算且 ECharts 内部尺寸（字号/半径）不随 rem 自动缩放；vw 在非 16:9 窗口会水平溢出。transform scale 对 DOM 与 canvas 一视同仁，且实现集中于一个 composable，改动面最小。

## 七、数据流与联动机制

### 7.1 单一数据源（SSOT）原则

- **唯一事实数据**：`screenStore.snapshot`（MockEngine 每 tick 产出的全量快照）；
- **唯一过滤状态**：钻取栈 + 两个类型维度选择，全部存于 `screenStore`；
- **唯一派生口径**：所有图表消费的视图数据一律由 `getters` 计算，**图表组件与视图层禁止自行过滤/聚合**（口径一致性约束 5 的代码级保障）；
- 组件本地仅允许 UI 态（hover、动画中间量），凡"业务数据"出现第二份副本即视为设计违例。

### 7.2 实时刷新链路（FR-10/11/12）

```
MockEngine（setInterval 5s，可配置 NFR-11）
    │ tick：模拟时钟推进 → 实体演化 → 聚合 → Snapshot
    ▼
screenStore.applyTick(snapshot)          # state 整体替换（浅层引用替换，触发响应式）
    │ Vue 响应式调度（同一 microtask 批处理，天然合帧）
    ├─▶ getters 重算（filteredKpi / filteredIntersections / ...）
    │
    ├─▶ KpiCard×4        props.value 变化 → CSS 数字过渡（无 JS 帧循环）
    ├─▶ MapChart         useECharts.watchDeps → setOption(merge) 只更新 series.data
    ├─▶ Rank/Pie/Ring    同上，merge 更新 data + 排序
    ├─▶ TrendChart       追加尾部点（appendData 语义，窗口滚动 shift）
    └─▶ HeatChart        仅当前时段格 data 更新
    全部动画时长 ≤ 400ms（NFR-02），单 tick 重绘总阻塞目标 < 100ms（NFR-04）
```

**暂停/恢复的连续性设计（FR-11 关键）**：`togglePause` → `engine.pause()` 同时做两件事——`clearInterval` 且**冻结模拟时钟 simTime**（而非让时钟空转）。恢复时 simTime 从冻结点继续推进，噪声相位与随机游走项无缝衔接，因此"恢复后首批数据与冻结前数值连续"由构造保证，无需额外补偿逻辑。

### 8.2 权重表（constants.ts）

**层级基准链**：`全局基准（如全国在途基准 3,200,000 辆）× 省权重 × 市占省比 → 市级 base`；省级/全国值**不直接生成**，一律由下辖市自下而上聚合（口径一致性约束 5）。非内置省份（无城市明细）例外：直接按省权重生成省级实体（仅服务全国视图热力，永不下钻）。

| 权重表 | 示例取值（最终以 constants.ts 为准） | 用途 |
| --- | --- | --- |
| 省份权重 provinceWeight | 广东 1.00、江苏 0.92、浙江 0.86、山东 0.80、四川 0.74、河南 0.76、其余 0.30~0.65 | 在途车辆、流量、事故密度、路口数的基数缩放 |
| 城市权重 cityShare | 省内一线/省会 ≈ 0.30、副中心 ≈ 0.12、普通地市 0.03~0.08（省内合计归一） | 市级 base 分配 |
| 路口权重 | 0.6~1.4 均匀分布 | 路口流量差异化 |
| 车辆结构占比 | 小汽车 62%、电动车 17%、货车 13%、公交车 8%（±3pp 地区微扰后归一） | 车辆类型统计与口径闭合 |

### 8.3 平滑噪声模型（数值连续性核心，约束"相邻变化 ≤ ±15%"）

每个指标通道维护独立正弦相位 φ₁、φ₂ 与有界随机游走项 w：

```text
raw(t) = base × weight(region) × hourFactor(h(simTime))
       × ( 1 + A₁·sin(2π·t/T₁ + φ₁) + A₂·sin(2π·t/T₂ + φ₂) )
       + w(t)

w(t) = clamp( w(t-Δ) + σ·N(0,1),  −W_max, +W_max )        # 有界随机游走
       （W_max = 8% × base：累计漂移有界，σ = 1% × base）

连续性钳制（输出前最后一道闸）：
value(t) = clamp( raw(t),  0.85 × value(t-Δ),  1.15 × value(t-Δ) )
         → 再 clamp 到业务值域（congestionIndex∈[0,10]、avgSpeed∈[15,80]…）

参数建议：T₁=300s（慢波）、T₂=40s（快波）、A₁=0.10、A₂=0.05
```

设计意图：正弦双波提供"有节奏的呼吸感"，游走提供"不可预测性"，双重 clamp 从数学上排除数量级跳变；暂停期间 simTime 冻结 ⇒ 所有相位连续 ⇒ 恢复即无缝（7.2 节）。

### 8.4 早晚高峰双峰函数（hourFactor，日内规律）

```text
G(h; μ, σ) = exp( −(h−μ)² / (2σ²) )                        # 高斯核

hourFactor(h) = 0.16                                        # 深夜低谷基线（0—6 时 ≈ 0.16~0.25）
              + 0.62 · G(h; 8.0, 1.3)                       # 早高峰（7—9 时，峰值 ≈ 0.78）
              + 0.78 · G(h; 18.0, 1.6)                      # 晚高峰（17—19 时，峰值 ≈ 0.94，高于早高峰）
              + 0.30 · bump(h)                              # 日间平台（10—16 时）
bump(h) = h∈[10,16] ? sin(π·(h−10)/7) : 0
```

特性校验：深夜低谷 ✓、双峰且晚峰略高 ✓、平滑无台阶 ✓。**车辆类型的时段形状差异**（联动过滤后的热力差异，7.4 矩阵）：小汽车用标准 hourFactor；公交车双峰更尖（σ 收窄至 1.0）；货车改为 8—17 时宽平台 + 深夜小峰（无通勤峰）；电动车晚峰放大 1.2 倍。

### 8.5 指标相关性（约束 4）

```text
congestionIndex = clamp( 3.2 + 3.6·hourFactor(h) + 噪声, 0, 10 )     # 高峰更堵
avgSpeed        = clamp( 58 − 3.8·congestionIndex + 微噪, 15, 80 )    # 与拥堵负相关（拥堵 2→~50km/h，8→~27km/h）
activeVehicles  = base × hourFactor(h) × 噪声                        # 高峰在途多
accidentCountToday：泊松式增量——每 tick 新增起数 ~ Poisson(λ)，λ ∝ 省权重 × hourFactor，
                   bootstrap 时按"当日已流逝小时 × hourFactor 曲线积分"预置基数（当日口径，只增不减）
```

### 8.6 引擎调度与模拟时钟（engine.ts）

```text
class MockEngine（全局单例）
  config：intervalMs=5000、accel=60（时间加速系数）、随机种子（可选，答辩可复现）
  start()：
    1) bootstrap：构建全量实体 + 按 hourFactor 回放过去 24h 趋势序列（288 点/地区）
    2) setInterval(intervalMs, tick)
  tick()：
    simTime += intervalMs × accel            # 1 真实秒 = 60 模拟秒 → 趋势与热力可见地滚动
    逐实体演化（8.3 公式）→ 事故增量 → aggregate 自下而上聚合 → 产出 Snapshot
    → onSnapshot(snapshot) 回调（由 Store 注入 applyTick）
  pause()/resume()：clearInterval 且冻结 simTime / 反之
  dispose()：清 interval（路由离开必须调用）
```

`accel=60` 的设计意图：趋势窗口 24h（288 点）在 24 分钟真实时间内滚完，热力"当前时段"每小时推进 1 分钟，答辩 15 分钟可完整看到模拟日内规律变化——演示节奏与真实感兼得；参数集中于 config（NFR-11）。

### 8.7 聚合口径（aggregate.ts）

```text
province.activeVehicles     = Σ city.activeVehicles
province.accidentCountToday = Σ city.accidentCountToday
province.avgSpeed           = Σ(city.avgSpeed × city.activeVehicles) / Σ activeVehicles   # 加权
province.congestionIndex    = 算术平均 + 微噪，clamp 值域
CHINA                       = 对 34 省（含非内置省）同法聚合
断言（开发期）：Σ vehicleType.activeCount == activeVehicles；Σ ratio == 100%
```

聚合只存在于引擎层（图表永不做聚合——SSOT 的数据侧延伸）。

## 十、关键技术点与风险

### 10.1 地图动态注册（MapRegistry）

- geoJSON 不随首屏全量加载：`import.meta.glob('./assets/geo/*.json')` 生成懒加载器映射，`load(code)` 返回 Promise，`echarts.registerMap(code, geoJSON)` 后写入已注册缓存（**同名重复 registerMap 有泄漏风险**，缓存判重是硬要求）；
- 切层不销毁实例：`setOption({ series: [{ map: code, data: ... }] })` 原地换装（防闪烁/防泄漏，见 5.3 MapChart）；
- **名称对齐**：DataV geoJSON 的 `properties.name` 多为全称（"广东省""广州市"），业务实体统一以 adcode 为主键、维护 `adcode → geoName` 映射表，数据侧 name 一律经映射表转换，杜绝"数据有值但地图不上色"的经典事故。

### 10.2 geoJSON 体积控制

| 措施 | 说明 |
| --- | --- |
| 来源精简 | DataV areas_v3 全量 json 已含冗余 properties，入库前脚本裁剪至仅 `name / adcode / center / centroid`，坐标不做抽稀（保轮廓精度，省界视觉重要） |
| 体积预算 | 全国 ~1.4MB + 4 省 ≈ 2.4MB + 4 市 ≈ 1.2MB，合计 ≈ 5MB |
| 分片策略 | 全部经 Vite 构建为**独立异步 chunk**（JSON 超 4KB 内联阈值自动外置；用 import.meta.glob 懒加载），首屏仅请求 china.json，省级/市级 chunk 下钻瞬间才拉取（本地打包静态资源，断网可用 NFR-07） |
| 首屏指标 | 主 bundle（Vue+Pinia+ECharts 按需）目标 ≤ 900KB gzip 前，加 china.json 首屏 < 3s（NFR-01） |

### 10.3 ECharts tree-shaking 与重绘开销

- 按需 `use([...])`（9.4 清单），预估较全量引入削减约 40%~50% 体积；
- 单 tick 十余图表重绘：一律 **merge setOption 只更新变化字段**（series.data），禁止整屏 notMerge；Vue 响应式在同一 flush 批处理内触发全部 watch，天然合帧；KPI 数字用 CSS 过渡零 JS 开销——共同保障 NFR-04（主线程阻塞 < 100ms）。

### 10.4 防内存泄漏（NFR-12 长时运行 2 小时验收的保障清单）

| 泄漏源 | 对策（全部收敛在 useECharts / engine / adapter 三处） |
| --- | --- |
| ECharts 实例 | onBeforeUnmount dispose；地图切层不重建实例 |
| ResizeObserver | 与实例同生命周期 disconnect |
| 防抖定时器 | 统一由 composable 持有并在卸载时 clear |
| setInterval | 引擎全局单例唯一 interval，pause/route-leave 均清理 |
| 数据结构 | 趋势固定 288 点环形缓冲；活跃事故封顶 200 条；快照整体替换不追加历史 |

### 10.5 风险清单（R1~R10）

| # | 风险 | 影响 | 缓解措施 |
| --- | --- | --- | --- |
| R1 | geoJSON 与业务数据名称不匹配，热力/散点渲染空白 | 高（FR-01 直接失败） | adcode 主键 + 名称映射表（10.1）；上线前地图渲染冒烟检查 |
| R2 | geoJSON 体积拖慢首屏 | 高（NFR-01） | 异步 chunk 分片 + properties 裁剪（10.2） |
| R3 | ECharts 意外全量引入，bundle 超标 | 中 | setup.ts 统一注册入口 + 构建产物体积检查脚本/visuaizer 复核 |
| R4 | dispose/observer/timer 泄漏导致 2h 运行崩溃 | 高（NFR-12/AC-20） | 10.4 清单 + 长跑回归测试（含反复钻取/暂停） |
| R5 | transform scale 容器下 ECharts 事件/tooltip 坐标偏移 | 中 | zrender 基于 getBoundingClientRect 换算，理论正确；**列为首个 spike 验证项**（demo 页验证后再铺开） |

| R10 | 非内置省份点击无响应被评委视为缺陷 | 中（演示观感） | 降级提示明确列出可下钻省份清单（FR-03 交互友好化），并在 /about 说明设计取舍 |

## 十二、设计决策记录（ADR 摘要）

| # | 决策 | 备选方案 | 选择理由 |
| --- | --- | --- | --- |
| ADR-1 | 缩放采用 transform: scale（contain + 居中） | rem / vw 布局 | DOM 与 canvas 一视同仁、非 16:9 窗口零溢出、实现收敛于一个 composable |
| ADR-2 | 路由采用 hash 模式 | history 模式 | 静态托管/离线分发零配置，消除部署风险 |
| ADR-3 | geoJSON 仅内置全国 + 4 省 + 4 省会市，异步 chunk | 全量 34 省市内置 | 体积可控（约 5MB vs 30MB+），断网可运行；未内置地区走 FR-03 降级（需求方已确认） |
| ADR-4 | 联动状态收敛于 Pinia 单 Store（SSOT） | 事件总线 / provide-inject | 三维度过滤 + 钻取栈集中可测；杜绝组件网状通信与数据副本 |
| ADR-5 | 暂停 = 冻结模拟时钟 | 暂停时让时钟空转 | 冻结相位使恢复后数据天然连续（FR-11 无需补偿逻辑） |
| ADR-6 | 图例联动维度 = {事故类型, 车辆类型} | 另含"路口"维度 | 路口为最细粒度实体、无跨图表统计口径，强行全局过滤将导致其余图表无数据；路口柱项点击降级为本地高亮 + 详情强化（FR-07 之"如"为示例性表述，AC-06 验收不受影响） |
| ADR-7 | 模拟时钟加速系数 accel=60 | 实时同步（1:1） | 24 分钟滚完 24h 趋势窗口，答辩 15 分钟可观察完整日内规律，演示节奏最优 |
| ADR-8 | ECharts 实例切层复用（setOption 换 map） | 销毁重建 | 防闪烁、防泄漏、动画连贯 |
| ADR-9 | TypeScript 增强类型契约 | 纯 JS | 实体/Props/Store 契约显式化（类型安全），答辩技术亮点；不与任何锁定决策冲突 |
