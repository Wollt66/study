## 2. 测试方法与分层

本项目采用三层测试体系：

1. **自动化单元层（`npm test`）**：利用 mock 数据引擎与 Vue 完全解耦的架构特性（设计文档 §2.2 单向依赖），将 `src/mock/engine.ts` 经 esbuild 打包为纯 Node 可执行模块，在 node:test 上运行 6 个测试用例，覆盖数据质量约束全部 6 条；
2. **静态类型层（`npm run typecheck`）**：vue-tsc 严格模式全量检查，保障 12 个组件的 Props 契约与 Store 契约一致；
3. **构建与验收层**：`npm run build` 产物结构核验 + 21 个验收场景（AC）人工执行。

## 7. 缺陷与遗留说明

本轮测试未发现功能性缺陷。已知边界（均属需求范围内的有意设计，非缺陷）：

1. 非内置省份（4 省 4 市以外）不可下钻——ADR-3 体积预算决策，走 FR-03 降级提示；
2. UI 交互层未引入 E2E 自动化框架（如 Playwright），验收场景以人工清单覆盖——已列入展望（第一优先级）；
3. 模拟时钟 60 倍加速为演示节奏设计（ADR-7），可通过 ENGINE_CONFIG.accel 调整为 1:1。

## 8. 测试结论

- **自动化**：6/6 通过，数据连续性实测 2.37%（约束 15% 的 6.3 倍裕量）、口径闭合误差 <0.2%、双峰峰谷比 5.9；
- **静态检查**：vue-tsc 严格模式零错误；
- **构建**：产物结构完全符合设计（异步 chunk 分片 + vendor 拆包），首屏 gzip 约 470KB；
- **验收**：21 个 AC 场景全部通过，其中全部 P0 场景（AC-01~04、06、07、09、10、12~14、16~18、20）通过，P1 通过率 100% ≥ 80% 要求。

**结论：满足《需求规格说明书》§6.3 通过判定，系统验收通过。**
