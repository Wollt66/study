## 分步脚本

| 步骤 | 操作动作 | 预期现象 | 耗时 |
| --- | --- | --- | --- |
| 1 | 打开/切到大屏页面 | 3 秒内完整呈现首屏 | 20s |
| 2 | 鼠标悬停不动，静置 | 5s 周期刷新、KPI 脉冲 | 20s |
| 3 | 点击地图【广东省】 | 下钻市级视图、全图表联动 | 30s |
| 4 | 点击【广州市】→ 连点两次"返回上一级" | 区县视图 → 逐级回退 | 30s |
| 5 | 点击事故玫瑰图【追尾】扇区，再点一次 | 全屏按事故类型过滤/恢复 | 30s |
| 6 | 点击车辆环形图【小汽车】图例 | TOP10 按类型重排 | 25s |
| 7 | 点击【暂停刷新】→ 等 10 秒 → 恢复 | 冻结标示、恢复无跳变 | 25s |
| 8 | DevTools → Network → Offline | 全部功能照常 | 20s |
| 9 | 拖拽缩放浏览器窗口 → 切全屏 | 等比重适配 | 20s |

**合计约 220 秒（3 分 40 秒），含操作间隙约 4 分钟。**

### 步骤 1｜首屏与整体布局（20 秒）

- **操作动作**：把浏览器切到前台，展示大屏首屏（若已打开则刷新一次，顺便证明冷启动速度）。
- **预期现象**：3 秒内完整呈现——全国地图热力 + 事故涟漪散点、左侧四张 KPI 指标卡、五类专题图表、顶部时钟与控制条。
- **讲解话术**："这是系统唯一的主界面。左边是四项核心指标，中间是全国路况热力和事故散点，右边和底部是五类专题图表。整个页面按 1920×1080 设计稿构建，刚才的加载在 3 秒以内完成。"
- **耗时**：20 秒。

### 步骤 2｜实时刷新观察（20 秒）

- **操作动作**：不做任何操作，鼠标移开，静置约 15 秒让评委自然观察。
- **预期现象**：每 5 秒全部图表平滑刷新一次：KPI 数字轻微脉动、排行条长度渐变、地图热力颜色渐变、趋势曲线尾部追加数据点。
- **讲解话术**："大家可以看到数据每 5 秒自动刷新一轮，注意数值是渐变过去的、不是跳变——这背后是我在数据引擎里做的连续性噪声模型，第 7 分钟汇报时展开讲过。"
- **耗时**：20 秒。

### 步骤 3｜省级下钻（30 秒）

- **操作动作**：点击地图上的【广东省】区域。
- **预期现象**：地图平滑切换为广东市级区划视图（热力变为各地级市维度、事故散点重分布），同时左侧 KPI、右侧饼图/环形图/趋势图、底部热力、路口 TOP10 全部切换为广东省口径；顶部出现"广东省"过滤标签。
- **讲解话术**："我点击广东，地图下钻到市级视图。请注意不只是地图在变——左边的指标、右边的每一个图表、底部的分时流量，全部同步切成了广东省的口径，这就是 SSOT 架构下的全屏联动。"
- **耗时**：30 秒。

### 步骤 4｜市级下钻与逐级返回（30 秒）

- **操作动作**：点击【广州市】→ 展示区县级视图 → 点击卡片右上角"返回上一级"两次。
- **预期现象**：进入广州视图（区县边界 + 散点）；第一次返回回到广东省视图，第二次返回回到全国视图，图表与 KPI 逐级同步回退，返回无需重新加载（地图缓存生效，切换瞬时完成）。
- **讲解话术**："继续点广州，完成第三级下钻。现在点两次'返回上一级'——注意回退是瞬时的，因为地图注册后有缓存，切换时也不销毁图表实例。"
- **耗时**：30 秒。

### 步骤 5｜事故类型联动（30 秒）

- **操作动作**：点击右侧事故玫瑰图的【追尾】扇区 → 停顿 5 秒展示效果 → 再点一次同一扇区取消。
- **预期现象**：地图事故散点过滤为追尾类、KPI"今日事故数"变为追尾口径、FilterTagBar 出现"追尾"标签；再次点击后全部恢复。
- **讲解话术**："联动不止来自地图。我点'追尾'这个扇区，全屏就按事故类型过滤了——地图上只剩追尾事故的散点，事故数也变成追尾的口径，顶部出现过滤标签。再点一次取消，恢复全量。三维过滤条件可以叠加，比如在此基础上再选车辆类型。"
- **耗时**：30 秒。

### 步骤 6｜车辆类型联动（25 秒）

- **操作动作**：点击车辆环形图的【小汽车】图例项。
- **预期现象**：路口 TOP10 排行按小汽车流量口径重新排序，KPI 在途车辆数变为小汽车口径，散点过滤为涉事小汽车事故；FilterTagBar 出现"小汽车"标签。
- **讲解话术**："再选'小汽车'车辆类型——看左下角的路口排行，已经按小汽车的流量重新排序了，在途车辆数也变成了小汽车的口径。现在地区、车辆类型两个维度是叠加生效的。"
- **耗时**：25 秒。

### 步骤 7｜暂停 / 恢复刷新（25 秒）

- **操作动作**：点击控制条【暂停刷新】→ 用鼠标指向任意 KPI 数字静置约 10 秒（数值纹丝不动）→ 点击【恢复刷新】。
- **预期现象**：暂停后全部图表与 KPI 冻结、控制条明确标示"已暂停"；恢复后数据从冻结数值连续滚动、无跳变。
- **讲解话术**："讲解时数据一直跳会影响注意力，所以我做了暂停功能。点暂停——所有数字完全冻结。现在恢复——注意看，数据是从冻结的那个数接着变的，没有跳变。因为暂停时我冻结的是模拟时钟本身，正弦相位都停在原地，恢复就是无缝的。"
- **耗时**：25 秒。

### 步骤 8｜断网演示（20 秒）

- **操作动作**：打开 DevTools → Network 面板 → 勾选 **Offline** → 随意执行一次下钻 + 一次图例联动。
- **预期现象**：一切功能照常：下钻正常、联动正常、刷新正常（此时可顺口说"现在整个系统零网络请求"）。
- **讲解话术**："最后验证离线能力。我把网络断掉——下钻、联动、刷新全部照常。因为地图边界、数据引擎、字体全部本地打包，这个系统天生就是为断网答辩设计的。"（演示完取消 Offline 勾选）
- **耗时**：20 秒。

### 步骤 9｜自适应与全屏（20 秒）

- **操作动作**：拖拽缩小浏览器窗口到约一半大小 → 观察等比缩放 → 再拖回 → 按 ESC/F11 切换全屏一次。
- **预期现象**：窗口变化时大屏整体等比缩放、内容零裁切零错位、留白区为深空背景；全屏切换后重新贴合。
- **讲解话术**："不管现场投影是什么分辨率，大屏都按 1920×1080 基准等比缩放，不会裁切也不会出滚动条。全屏模式一键切换。以上就是完整演示。"
- **耗时**：20 秒。

## 风险预案（4 条，务必演练）

### 预案 1｜现场断网 / 网络不可用

- **处置**：**无需处置——这本来就是离线方案**。`npm run preview` / `npm run dev` 起的是本机回环服务（localhost），不依赖外网；geoJSON、模拟数据、字体全部本地打包，运行期零外网请求。
- **话术**："正好，各位老师可以现场检验这个系统的离线设计——它本来就不需要网络。"（把意外变成加分项）
- **底线方案**：若本机彻底无法起服务（极端情况），用提前录好的演示视频兜底（提前录一份带鼠标操作与解说的完整版存本地）。

### 预案 2｜浏览器卡顿 / 分辨率异常 / 投影错位

- **处置**：①先 `Ctrl+R` 刷新一次（多数偶发卡顿自愈）；②按 F11 进全屏（消除浏览器 chrome 干扰，并触发缩放重算）；③若投影分辨率异常导致模糊或比例怪异，口头说明"系统按 1920×1080 基准等比缩放，当前是投影端的显示问题，内容无缺失"，然后继续演示功能；④演示前关闭无关标签页与高 CPU 程序。
- **话术**："大屏会自动适配当前分辨率，我先切个全屏让它重新贴合。"

### 预案 3｜地图点击没反应

- **先判断两种情况**：
  - **点到未收录省份**（如山东、河南等非内置区域）→ **这不是故障，是设计**："这个省份的边界数据没有内置——我在设计时基于体积预算做了裁剪决策，只内置了四个代表性省份，未收录区域会给出降级提示并列出可下钻清单。"（顺势把 FR-03 降级设计与 ADR-3 讲成亮点，然后改点广东/江苏/浙江/四川继续演示）；
  - **点在海面或省界边缘**（未命中任何 feature）→ 把鼠标移到省份几何中心再点一次，不用解释。
- **话术**（未收录时）："注意这里出现了提示——这是我做的降级交互，明确告诉用户哪些区域可以下钻，而不是点了没反应。"

### 预案 4｜演示时间不够（评委压缩时间）

- **保留核心四步**（不可删，合计约 2 分钟）：步骤 3 省级下钻 → 步骤 5 事故类型联动 → 步骤 6 车辆类型联动 → 步骤 7 暂停/恢复；
- **可跳过**（口头带过即可）：步骤 2 静置观察（"数据每 5 秒刷新一轮"一句话带过）、步骤 8 断网（"系统离线可运行，刚才全程零网络请求"一句话带过）、步骤 9 缩放全屏（"任意分辨率等比自适应"一句话带过）、步骤 4 的市级下钻可压缩（只下钻不返回）；
- **压缩后 2 分钟版顺序**：下钻广东 → 点广州（不返回）→ 点追尾 → 点小汽车 → 暂停恢复 → 一句收尾。
