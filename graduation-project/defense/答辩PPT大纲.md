### 第 2 页｜选题背景与意义（50 秒）

**页面内容要点（讲稿级）**：

- 背景三层递进：①城市化进程下交通拥堵成为大城市治理的核心痛点，交通管理部门需要"一屏总览"的态势感知工具；②指挥中心大屏是交通监控场景的标准载体，其技术本质是"高密度数据可视化 + 实时刷新 + 多维度联动研判"；③这类大屏的工程难点不在单个图表，而在**联动架构、实时数据流与多分辨率适配**的系统性问题上——这正是本课题的研究价值；
- 选题定位说明（主动讲，不给评委留疑问）：本课题选择纯前端路线，把工作量聚焦在可视化工程本身的深度上：地图钻取、状态联动、数据连续性、性能与离线能力，而非后端服务的广度；
- 意义落点：交付的不仅是一个演示页面，而是一套"需求→设计→实现→测试"完整工程方法论的实践（EARS 需求 33 条、9 项设计决策 ADR、6 个自动化测试）。

### 第 4 页｜技术栈与总体架构：五层单向依赖（70 秒）

**页面内容要点（讲稿级）**：

- 技术栈逐项报出并各带一句"为什么"（一句话即可，详细理由留给 Q&A）：Vue 3.5 组合式 API + TypeScript 严格模式（类型契约）、Vite 6（构建与代码分片）、Pinia（SSOT 状态管理）、vue-router 4 hash 模式（离线零配置）、ECharts 5.6 按需引入（体积控制）；
- 五层架构图讲解（本页视觉主体，自底向上讲数据流）：
  - **L1 资源层**：9 份 geoJSON（本地打包）、ECharts 按需注册、霓虹设计令牌；
  - **L2 Mock 数据引擎层**：纯 TypeScript、零框架依赖——时钟调度、噪声模型、自下而上聚合；
  - **L3 状态层**：Pinia 单 Store，全系统唯一数据源（SSOT）；
  - **L4 组合函数层**：useECharts（实例生命周期托管）、useScreenAdapter（等比缩放）；
  - **L5 视图层**：12 个组件（KpiCard×4 + 6 类图表 + 布局/控制组件）；
- 强调两条架构铁律（这是后面所有亮点的地基）："**单向依赖，严禁反向**——mock 引擎不知道 Vue 的存在，所以能独立跑单元测试；**数据自底向上流、事件自顶向下流**——数据从引擎流向 Store 再流向图表，交互从组件回到 Store，组件之间永远不直接说话。"

**建议配图**：按 `design/架构图.puml` 转绘霓虹风格分层图（L1 在底部、L5 在顶部，右侧画一条向上的"数据流"箭头和一条向下的"事件流"箭头）；左下角小字标注"12 个视图组件 · 单向依赖"。

**时长**：70 秒。

### 第 5 页｜亮点 1：地图三级钻取（70 秒）

**页面内容要点（讲稿级）**：

- 先给效果：全国地图点击广东省 → 切到该省市级区划图 → 再点广州 → 切到广州区县图；卡片右上角"返回上一级"逐级回退，全部图表同步切换维度；
- 讲三个工程决策（每条 15 秒左右）：
  1. **离线地图方案**：ECharts 5 起不再内置中国地图，我基于阿里 DataV areas_v3 边界数据，用自写脚本裁剪（只保留 name/adcode/center/centroid 四个字段）后本地打包 9 份 geoJSON（全国 + 广东/江苏/浙江/四川 + 广州/南京/杭州/成都），实测总体积仅 **1.49MB**，且经 Vite 构建为**异步 chunk**——首屏只加载全国图，省市图在下钻瞬间才拉取，断网环境完整可用；
  2. **实例复用**：切层级不销毁 ECharts 实例，只 `setOption` 原地换 map——不闪烁、不泄漏、动画连贯；
  3. **降级设计**：未收录的省份/城市点击时给出明确提示并列出可下钻清单，当前视图与数据保持不变——把"功能边界"做成"交互引导"。
- 抛一个数字细节体现严谨：registerMap 做了缓存判重，避免同名重复注册的泄漏风险。

**建议配图**：三联截图并排（全国热力图 / 广东市级图 / 广州区县图），之间用箭头串联标注"点击广东 → 点击广州"；右下角小截图放降级提示的 UI；左下角放一个"9 份 geoJSON = 1.49MB · 异步 chunk"的徽章。

**时长**：70 秒。

### 第 6 页｜亮点 2：多图表联动：SSOT 架构（80 秒）

**页面内容要点（讲稿级）**：

- 先定义问题（体现思考深度）："大屏联动最大的坑是**状态漂移**——如果每个图表自己记一份'当前过滤条件'，一旦从别处解除过滤，各图表状态就会不一致。我的解法是 SSOT。"
- SSOT 数据流讲解（对着图讲）：
  - 全部业务状态收敛在**一个 Pinia Store**：`snapshot`（当前全量数据快照）+ `regionStack`（地区钻取栈）+ `selectedVehicleType` + `selectedAccidentType`；
  - **三个全局过滤维度**：地区维度（由钻取栈栈顶决定）、车辆类型维度、事故类型维度——任何入口的修改都只改 Store；
  - 12 个视图组件全部是"无业务状态的渲染器"：只消费 Store 的 getters 派生结果，**禁止自行过滤或聚合数据**——这从代码层面保证了 KPI 卡、排行、饼图、散点看到的是同一个口径；
- 交互闭环举例（10 秒讲一个完整链路）："我点事故玫瑰图的'追尾'扇区 → 事件经 ScreenView 转发到 Store → 事故类型维度置为'追尾' → getters 重算 → 地图散点只显示追尾事故、KPI 今日事故数变成追尾口径 → FilterTagBar 出现'追尾'标签，点它可以一键解除——**一个事件，全屏 12 处同步变化，且永远一致**。"
- 再点一句地区维度："地区维度用栈结构实现，逐级返回就是出栈，天然支持 FR-04 的逐级回退语义。"

**建议配图**：SSOT 数据流辐射图（中央 Pinia Store 圆角大节点，内部分四格：snapshot / regionStack / vehicleType / accidentType；向四周辐射 12 个组件节点，箭头标"getters 派生 → props 下发"；另一组反向箭头标"emit 事件 → action 修改"）；角标放 FilterTagBar 实际截图。

**时长**：80 秒。

### 第 7 页｜亮点 3：实时刷新与数据连续性（90 秒 · 全场技术密度最高的一页）

**页面内容要点（讲稿级）**：

- 先讲刷新机制："模拟数据引擎以 **5 秒周期**推送全量快照，大屏所有图表以平滑动画过渡；引擎内部有一个 **60 倍加速的模拟时钟**——1 真实秒等于 60 模拟秒，所以 24 分钟就能滚完一个完整模拟日的 24 小时趋势，答辩现场能亲眼看到早晚高峰的到来与消退。"
- 核心讲噪声模型（对着公式讲，这是本页的学术分量）："随机数直接刷新会跳变，我设计了**双正弦 + 有界随机游走 + 双重钳制**的三层噪声模型"：
  1. **双正弦波**（慢波 T₁=300s / 快波 T₂=40s）提供'有节奏的呼吸感'；
  2. **有界随机游走** w(t) = clamp(w(t−Δ) + σ·N(0,1), −8%·base, +8%·base) 提供不可预测性，且累计漂移有界；
  3. **连续性钳制**（最后一道闸）：value(t) = clamp(raw, 0.85·value(t−Δ), 1.15·value(t−Δ))，再钳到业务值域——**从数学上排除数量级跳变**；
- 用实测数字收尾（最有力的部分）："需求约束是相邻变化 ≤ ±15%，我用自动化测试实测相邻快照变化仅 **2.37%**——远优于约束，且观感是'数据在呼吸'而不是'数据在抽奖'。"
- 暂停/恢复的连续性设计："暂停不是简单停掉定时器——我**冻结的是模拟时钟本身**。所有正弦相位、游走状态在冻结点静止，恢复时时钟从冻结点继续推进，相位无缝衔接，所以恢复后的第一批数据和冻结前天然连续，**不需要任何补偿代码**，这是'由构造保证正确'的设计。"
- 顺带报数据规模体现真实感："引擎管理 34 省、66 市、864 个路口的实体演化，每 tick 自下而上聚合出全国快照。"

**建议配图**：上半页放"三层噪声模型"公式卡片（三张霓虹圆角卡片横排：双正弦 / 有界游走 / 双重钳制，各配一行公式与一句人话注释）；下半页左侧放 24 小时分时流量热力截图（标注"晚峰 598,494 辆/h vs 深夜谷 101,716 辆/h，峰谷比约 5.9 倍"），右侧放"实测：相邻快照变化 2.37% ←→ 约束 ±15%"的大号对比徽章。

**时长**：90 秒。

### 第 8 页｜视觉设计与大屏自适应（50 秒）

**页面内容要点（讲稿级）**：

- 视觉系统："赛博朋克霓虹风格——深空底色 #050816、霓虹青/品红/紫渐变高亮、关键元素辉光、全模块圆角卡片（≥12px）；ECharts 主题不是官方现成主题，而是自研的 neon 主题注册（`registerTheme('neon')`），全屏图表一处定义全局生效。"
- 讲一个"细节见功力"的点："拥堵五级色带（畅通/基本畅通/轻度/中度/严重）在 KPI 指标卡、地图热力 visualMap、悬浮 tooltip **三处引用同一份常量**——从机制上杜绝'同一数据两处颜色不一样'的视觉事故。"
- 自适应方案："以 1920×1080 为唯一设计基准，`transform: scale` 等比缩放（取 min 比例保证任何窗口都不裁切，宽边留白用深空背景填充成有意的构图）；缩放算法收敛在一个 composable 里，1366×768 到 2560×1440 全覆盖，窗口拖动实时重算，支持一键浏览器全屏。"
- 一句选型依据（给 Q&A 留钩子）："对比过 rem 和 vw 方案——rem 不会自动缩放 ECharts 内部字号，vw 在非 16:9 窗口会溢出，transform 对 DOM 和 canvas 一视同仁。"

**建议配图**：左侧设计令牌色板（五级拥堵色带条 + 霓虹调色盘色块）；右侧同一大屏在 1366×768 / 1920×1080 / 2560×1440 三种分辨率下的三联截图（体现"零裁切零错位"）。

**时长**：50 秒。
